## Conventions

The why behind choices that no config file confesses. Every item here was a decision; treat edits to them as decisions, not edits.

- **Font wiring lives entirely in `src/index.css`**; `src/main.tsx` boots React only. The stack order `'Vazirmatn', 'Inter Variable', 'Inter', sans-serif` is load-bearing: the Vazirmatn UI-FD-NL variant has no Latin glyphs, so Latin text and digits fall through per glyph to Inter Variable, then locally installed Inter. Never reorder it; never move wiring into JS.
- **`src/font/vazirmatn/` is a verbatim byte-level vendor copy** from the owner's Desktop font folder. Never edit, format, or lint it; adding weights is a re-copy, not a regeneration. `.prettierignore` enforces the format side.
- **`tailwindStylesheet` in `.prettierrc.json` must keep pointing at `src/index.css`** — prettier-plugin-tailwindcss requires the Tailwind v4 stylesheet entry point for class sorting.
- **Theming is preference-backed with system default**: the html element carries the `dark` class (docs-exact `@custom-variant dark`); the inline bootstrap script in `index.html` resolves Theme preference vs System theme pre-paint and listens for OS changes; the React picker (`src/theme-picker.tsx`) writes the `theme` localStorage key — `light` / `dark`, absent = system, picking system removes the key rather than storing it. Native chrome and backgrounds follow the resolved class (`color-scheme: light` base / `color-scheme: dark` on `.dark`), backgrounds white / zinc-900.
- **First paint is theme-correct before the module graph**: `index.html` carries a critical `<style>` block whose `html` / `html.dark` pairs must mirror the base background tokens exactly — `#fff` (`--color-white`) and `oklch(21% 0.006 285.885)` (`--color-zinc-900`) — with the matching `color-scheme`, so the resolved theme paints before Vite's dev CSS injection or the production stylesheet arrives; change both places together when the base pair moves. The bootstrap's storage reads are guarded, so blocked storage falls back to the System theme instead of aborting the script.
- **UI primitives live in `src/components/ui/`**: `Button`, `Tooltip`, and `DropdownMenu` are the shared building blocks, and `use-anchored-position.ts` is the only positioning authority for floating layers. Overlays render through a portal with fixed viewport coordinates, flip when they hit an edge, and clamp inside 8px of the viewport — never position an overlay with `absolute` inside a scroll container. `DropdownMenu` traps focus while open: Tab cycles among the items and only highlights them, while Enter, Space, or a pointer click commits the item, closes the menu, and returns focus to the trigger so the same key reopens it; Escape or a click outside closes without committing. `ThemePicker` composes these primitives and owns only Theme preference.
- **Never start a dev server**: `bun run dev`, `vite`, `vite preview`, and any watch server belong to the owner. Agents make the changes, verify with `bun run build`, `bun run lint`, and `bunx prettier --check .`, inspect `dist` when css changed, then hand the tree back — the owner runs the app and tests it live. Do not open a browser against a server an agent started.
- **Dist is the only css witness**: a green `bun run build` proves nothing about css — a css file not imported anywhere is silently invisible, and theme variables only emit when referenced. After any css change, read the compiled `dist/assets/*.css` before declaring the work done.
